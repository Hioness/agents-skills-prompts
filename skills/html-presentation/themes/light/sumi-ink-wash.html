Overview v2.2

Single-file HTML documents for presenting complex technical output — specs, plans, code reviews, research synthesis. Every element earns its place on the page. This is SUMI: ink on washi, the same system reimagined in the language of the brush and the seal.

The page is itself an implementation of the system. Each component shown here can be copied as-is. The ink-load hierarchy — 濃 to 薄 — carries the depth that dark backgrounds did: heavier ink for headings and structural truth, dilute washes for numbers and labels.

The aesthetic, stated plainly. Washi paper, sumi ink, one vermilion seal. No gradients, no novelty type. Verbose decoration is noise; the brush is precise. Honor prefers-reduced-motion and a print theme that renders to legible paper.

Layout mokuroku sidebar

Left catalog rail — a 目録 (mokuroku) of the document's sections. Expanded, each row pairs the section kanji with its label; the active entry carries a thin vermilion edge and a pale wash. Collapsed, it folds to a scroll spine — a column of kanji with the catalog title written vertically down the edge and a small seal at the foot. Hovering the collapsed rail fans out every section's label as an unrolled paper tab — an instant side-legend of the catalog, with the hovered entry marked in vermilion. The vermilion 三 toggle folds and unfolds the catalog. Title block, content column (920px centered), footer. SVG diagrams use min-width: 520px and scroll horizontally rather than downscale.

Export shell. One document-level export lives in the footer — copy markdown. Nav meta is version + date only, sealed as a small stamp.

Analysis grid — yin/yang trade-off

〇 / × glyphs survive print and copy. Use only for genuine trade-offs — if the decision is obvious, state it as a recommendation without the grid.

Pros

  • Both heading levels visible — no cycling blind
  • Fixed toolbar width — no layout shift on toggle
  • Trigger button doubles as state indicator
  • Familiar pattern from rich-text editors

Cons

  • Two clicks required — open popup, then select
  • Popup dismisses on accidental outside click
  • More implementation complexity than a cycle button

Recommendation

Pattern 01 (Split H1/H2) is the strongest choice for this toolbar. Both heading levels are always visible, the toolbar width stays fixed, and there is no cycling blind. Implementation is straightforward.

Pattern 02 (Cycle) is the best runner-up if minimalism is the constraint — it matches the existing font-picker behavior and adds only one DOM element.

Writing Rules 21 rules

RuleDetail
justify every elementRemove what changes nothing for the reader.
section titles are nouns"Migration Plan" not "Migrating the Database". Action goes in prose.
nav title formatscope / document-type. The seal marks the brand, not a button.
one export, footer onlyExactly one document-level export: copy markdown. Nav meta is version/date only, sealed.
no invented export flavorsNo print, copy link, copy prompt, copy diff, copy JSON. Code-block copy stays.
no hero language in toolsDeveloper document, not a landing page. No taglines.
callouts are exceptionalOne per section is the ceiling. If every section has one, none are.
callouts annotate; recommendations concludeThe 済 stamp seals the verdict. Don't conflate them.
hanko communicate changeA seal is a state that could change. Static forever → it's a tag.
errors are instructionsState what happened and how to fix it. Never "something went wrong."
no lorem ipsumAll placeholder content must be plausible and domain-fit.
option numbers are zero-padded01 02 03 — ordered alternatives, not arbitrary headings.
analysis grids need real trade-offsIf the decision is obvious, recommend without the grid.
focus every interactive elementAll a and button get visible :focus-visible.
aria-hide visual-only elementsLine numbers, gutter sigils. aria-hidden="true".
print uses a dedicated themeLight paper rendering, tints bumped for white.
respect reduced motionNo transitions when prefers-reduced-motion.
clipboard needs fallback + feedbackWriteText → execCommand('copy') → flash "copy failed".
diagrams scroll, never downscale.diagram-svg with min-width: 520px.
